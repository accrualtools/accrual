$ACCR

Yield math for tokenized real-world assets. Day-count conventions, accrued interest, duration, convexity. It runs. In this page, as a CLI, and as an MCP server your agent can call.

the problem

Every tokenized treasury product quotes a yield. Almost none publish the day-count convention behind it. Same principal, same rate, same dates, six conventions, six different numbers. The spread is not rounding, it is money, and it is the first thing a settlement desk checks and the last thing a deck mentions.

install

One package, no dependencies. npm install accrual adds exactly one entry to your tree, which you can check yourself. Node 20 or newer. 

$ npm install accrual
added 1 package
// the same numbers the calculator above runs on
import { accrueSimple, bondMetrics } from 'accrual';

accrueSimple({
  principal: 1_000_000,
  rate: 0.0525,
  from: '2025-01-31',
  to: '2025-07-31',
  convention: 'ACT/365F',
});  // interest 26034.25

for agents

The same math as an MCP server over stdio, thirteen tools. It is a pure function over numbers: no RPC client, no signer, no key material anywhere in the package. It can value a position and cannot move one. Verify by reading the imports, there are none outside the source directory. 

// claude_desktop_config.json, or any MCP client
{
  "mcpServers": {
    "accrual": { "command": "npx", "args": ["-y", "accrual", "accrual-mcp"] }
  }
}
// tools exposed
day_count         every convention for one date pair, and the spread
accrue_simple     simple interest, plus the same result under all six
accrue_compound   compound interest and the effective annual rate
bill_yields       discount yield vs the yield you actually earn
bond_metrics      price, duration, convexity, cashflow schedule
present_value     one future cashflow, discounted
compare_products  two offers on the same footing
year_fraction     one convention, when you know which you need
loan_payment      level payment, total interest, first-payment split
loan_schedule     every row, closing at exactly zero
loan_payoff       what overpaying saves, in money and in months
loan_implied_rate the rate behind a payment, nominal and effective
loan_affordable   what a given payment can borrow
// or from a shell
$ accrual days   --from 2025-02-28 --to 2025-03-31
$ accrual bill   --face 100 --price 97.80 --settle 2025-01-02 --maturity 2025-07-03
$ accrual loan   --principal 200000 --rate 6% --years 30
$ accrual payoff --principal 200000 --rate 6% --years 30 --extra 200

Every number on this page is computed in your browser from the formulas in accrual.mjs. Nothing is fetched and nothing is reported. The library is MIT.

This is calculation software, not financial advice, not a quote, and not a valuation you should settle against. Day-count implementations follow ISDA 2006 section 4.16 and ICMA Rule 251; confirm the convention in your own documents before you rely on a number.

$ACCR is not a security and carries no claim, coupon or redemption right. pons does not audit or endorse tokens, and does not enforce unique names or symbols, so key on the contract address and never on the name.
